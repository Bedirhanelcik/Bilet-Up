# Screenshots

Real captures of the running app, not mockups. `README.public.md` already embeds these exact
filenames (homepage in the Preview section at the top, the rest under Screenshots) — once these
files exist here, the README just works, no further edits needed.

## Required (priority order)

1. - [ ] `desktop-homepage.png` — the landing page, first fold, real seeded event data. Shown at
        the very top of the README, right after the project description.
2. - [ ] `desktop-event-detail.png` — a real event's detail page.
3. - [ ] `desktop-events.png` — the Discover / event listing page.
4. - [ ] `desktop-organizer.png` — organizer dashboard, or a ticketing/QR check-in screen —
        whichever looks strongest.

## Optional

- [ ] `mobile-homepage.png` — only if it adds something the desktop shot doesn't already show.
      Don't pad the set past 5 total.

## How

- Desktop: ~1440×900 viewport, no browser chrome, no DevTools panel visible.
- Real seeded data on screen — not an empty state, not a loading skeleton.
- Pick whichever theme (light/dark) looks best per shot; consistency across the set isn't required.
